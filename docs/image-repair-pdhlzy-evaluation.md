# 新图片网关去字与背景修复实测

日期：2026-09-16。用户提供 `https://pdhlzy.art` 与 `https://pdhlzy.com`，授权复用对应的本地 CC Switch 凭据测试。

## 当前启用状态

用户在评估后明确选择先降低成本，当前本地去字、背景修复已切换到 **`gpt-image-2` / `https://pdhlzy.art/v1`**。文本翻译继续走原文本网关，OCR 和 AI 阅读继续使用百炼。下面保留切换前的质量对照，不能把用户接受成本取舍写成模型质量超过原模型。

图片密钥独立配置在服务端 `AI_IMAGE_GATEWAY_API_KEY`；`TRANSLATION_IMAGE_PROVIDER=openai`、`TRANSLATION_IMAGE_MODEL=gpt-image-2`。新修复步骤保存图片线路标识，已有成功修复继续复用；已经保存线路的旧步骤保留原线路和凭据。网络结果不确定时不自动换回付费原模型。

新增图片适配读取聊天响应中的单张 PNG，校验格式、大小和像素数；不访问模型随意返回的外部链接。图片原有透明度、局部合成和本地译文排版继续使用原处理流程。

## 首次评估结论（切换前）

**`gpt-image-2` 能通过该网关真实去字，费用明显低于之前使用的修复模型公开单价，但目前不替换 FormatOwl 的默认修复模型。** 渐变背景的两轮复测都出现可见色块接缝；网格线有轻微变化；纹理较接近原背景。尚未达到用户要求的效果不明显下降。

首次评估只增加本地测试和报告，没有修改网站配置。后续用户选择切换后的接入状态见上文。没有把模型出现在列表中等同于图片编辑验收通过。

## 接口与实际调用

- 两个地址的 `/v1/models` 均成功，当前密钥均返回 `gpt-image-2`、`gpt-image-2.5`、`gpt-image-2.5-flare`。
- 平台公开的接口元数据指向 **`POST /v1/chat/completions`**。请求使用 `messages` 中的文字与 `image_url`，`stream: false`；返回的聊天内容包含 PNG 的 base64 数据。
- `/v1/images/edits` 没有在本次得到验证，不能直接假定该网关与官方图片编辑协议相同。
- `.com` 完成 Python 客户端的七次真实图片请求；`.art` 额外完成一次 Node.js `fetch` 请求，核对 FormatOwl worker 所用运行时能够调用。共八次成功，没有自动重试。
- `.com` 的 Node.js 只读连接曾超时，`.art` 的 Node.js 只读和图片请求成功。未来接入可优先采用 `.art/v1`，但单次测试不构成长期稳定性承诺。
- 网关返回模型名只能证明所选路由和返回值，无法独立确认平台内部如何映射模型。

## 质量检查

使用已有的渐变、网格、纹理合成样本；它们有已知的无文字背景，能够检查模型是否改变背景。正式六次复测与原模型使用相同的源图、生产提示词、裁剪坐标和局部合成函数，各场景两轮。另一次初探使用更明确的网格提示词，一次 Node.js 请求复测渐变。

| 场景 | GPT Image 2 两轮观察                           | 原模型对照         | 决定                     |
| ---- | ---------------------------------------------- | ------------------ | ------------------------ |
| 渐变 | 原文字去掉，但修复框明显偏色，形成矩形接缝     | 背景衔接更自然     | 不替换                   |
| 网格 | 原文字去掉，局部线条厚度、颜色或位置有轻微变化 | 整体更接近已知背景 | 不作为保持版式的默认模型 |
| 纹理 | 第一轮较好，第二轮纹理变化稍多                 | 更稳定             | 保留候选，不据此全量替换 |

正式六次复测中，合成后修复区域外像素、原图透明度均保持不变。这由 FormatOwl 的本地合成保证，**不代表模型生成图本身保持了全部像素**。

辅助指标为修复框内 RGB 平均绝对误差（0–255，越小越接近已知背景），不是通用画质分数：

| 场景 | 当前原模型，两轮 | GPT Image 2，两轮 |
| ---- | ---------------- | ----------------- |
| 渐变 | 2.204 / 2.204    | 5.329 / 7.223     |
| 网格 | 2.249 / 2.249    | 3.236 / 3.795     |
| 纹理 | 1.691 / 1.691    | 1.631 / 2.767     |

当前模型对照复用此前已保存的结果，没有额外调用原模型。重复提交不保证网关内部没有缓存。未对照片、整页扫描 PDF 或完整翻译任务作本轮新增验收。

## 费用与速度

- 六次正式复测前后，同一令牌已用额度从 15,000 增至 105,000，增加 90,000。
- 平台公开状态为每计费单位 500,000 额度，显示币种 `CNY`，显示换算率为 1；因此这六次对应站内账面 **0.18 元，平均 0.03 元/次**。
- 初探一次、正式复测六次、Node.js 核对一次，共八次；以每次相同扣额计算为 **0.24 元站内额度**。最终额度快照见本地证据。
- 这是此密钥、当前分组、当前尺寸的站内计费记录；不把充值折扣、赠送额度或未来价格当成已验证的实际现金成本。
- 六次正式请求耗时 21.57–26.63 秒，中位数 22.64 秒；首次探测 79.29 秒，Node.js 核对 24.51 秒。
- 平台公开价格表中，同分组下 `gpt-image-2.5` 与 `gpt-image-2.5-flare` 的基础单次价格是 `gpt-image-2` 的十倍。本轮未调用它们，也不根据名称推断其去字效果。

降本优先处理已发现的纯色背景问题：把现有纯色判断移到收费请求之前；复杂背景再使用云端修复。该优化尚未在本轮实施。
